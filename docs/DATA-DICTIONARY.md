# 夜班工时与工资

班次属于shift_day；计划结束时间不大于开始时间时跨到次日。打卡是带偏移的时间，先存UTC，再用Asia/Shanghai拆分实际日历日。休息区间按夜班日期归属处理，先从实际工作区间扣除。单班最多18小时，打卡须为整分钟。缺IN或OUT整班隔离，不猜补卡。

按实际日历日判断法定假日、周末，法定假日优先3倍、周末2倍、工作日8小时内1倍、超过8小时1.5倍；正常分钟按同员工同日累计，跨班片段共享阈值。参数holidays可传日期列表，默认仅2026-10-01。金额按片段Decimal计算到分，paid为实发工资，差额为应发减实发。此规则用于样例计算，不替代当地劳动法规。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一员工/归属日/方向的最高版本若有时刻、时薪、班次、休息或实发金额冲突，则整班隔离；选中IN与OUT的时薪、班次起止与休息起止也必须完全一致。

## 付款月结（M8）

人事快照经 `parameters.roster` 传入（对象数组，字段：employee、pay_type=monthly|hourly、monthly_salary、hire_date、leave_date），校验失败返回 ROSTER 且不落任何半份结果。快照随结果封存为 `roster_snapshot` 并计算 `roster_hash`；原始打卡与人事实参只追加、不删除、不改写。未出现在快照里的员工按计时处理，保证旧批次口径不变。

**裁决：月薪员工加班基数 = 月结生效时快照月薪 ÷ 21.75 ÷ 8（即 ÷174 小时）**，与当月自然日、实际排班均无关。因此少排班不会压低基数；排班补录只产生新批次，改不动已复核月结的基数。时基保留四位小数用于算分，金额按片段 Decimal 四舍五入到分。

- 月薪折算（固定部分）= 月薪 × 在职自然日 ÷ 期间自然日；在职区间为 `[hire_date, leave_date]` 与期间交集，入、离职当日均计为在职日。只依赖入离职日期，不依赖排班。
- 计薪片段沿用 M5 切段。月薪员工：REGULAR（工作日8小时内）已被月薪覆盖，金额记 0 不重复计；OVERTIME 按（1.5−1）倍、REST 按（2−1）倍、HOLIDAY 按（3−1）倍时基计加成。跨夜片段按实际日历日判假日，越过节假日的部分拿3倍。
- 计时员工逐片段按打卡时薪×倍率计，应付与 M5 金额逐分对应；`balanced` 校验计时合计与 M5 一致、总分钟与切段守恒。
- 月结行含实际班次分钟、正常工时分钟、加成分钟、加班基数、折算月薪、应付与基数依据，四者一一对应。
- 期间取班次归属日的年月；员工有班次落在在职窗口外时整批 ROSTER 失败。

## 作废、重跑与付款

- 入离职、排班或规则变化会改变幂等键（输入字节+参数+规则版本），生成新 run_id；同一期间旧有效月结自动置为「作废」并登记替代批次，历史批次原件（含 source_b64 与人事快照）永久保留。
- 新结果在 `run()` 完整算成功后才写库；生成失败直接返回，旧有效月结不动。
- 同源重跑复用 run_id（INSERT 忽略），付款登记按 run_id 幂等：重复提交返回同一笔付款，不产生第二笔。
- 只有 status=有效 且 balanced 的月结可登记付款、可导出；作废单付款/导出返回 409 VOID。页面与导出只呈现这份有效月结，作废单仅出现在台账与历史批次中供审计。
